About This Tool

DO-178C (Software Considerations in Airborne Systems) and DO-254 (Design Assurance Guidance for Airborne Electronic Hardware) define the development assurance processes and evidence required for FAA/EASA certification of airborne software and hardware. The required evidence set is determined by the Design Assurance Level (DAL A through D), with DAL A having the most rigorous requirements.

This checklist helps development teams and DER/DAR reviewers verify that required lifecycle data and evidence is present, correct, and complete before submitting for FAA/EASA certification credit. Use one checklist per software or hardware item (LRU, function, component). Select your DAL level — questions not required at your DAL are grayed out automatically.

DAL ABCD

DAL ABCD

Section 2 — Requirements Data (DAL A–D)
SW-R1Software Requirements Data — Are high-level requirements (HLRs) documented, uniquely identified, and traceable to system requirements? Are HLRs testable and unambiguous?
ABCD
Ref: DO-178C §11.9 / §5 HLR development
SW-R2Low-Level Requirements (LLRs) — Are LLRs documented, traceable to HLRs, and sufficient to allow source code development without further design information? (DAL A/B/C)
ABC
Ref: DO-178C §11.10 / §5.3 LLR development / DAL C structural coverage at DC basis
Section 3 — Design & Source Code Data (DAL A–D)
SW-D1Design Description / Software Architecture — Is the software architecture/design description document present, showing the software structure, control flow, data flow, and interfaces?
ABCD
Ref: DO-178C §11.10 design description / §5.3
SW-D2Source Code — Is the source code present in configuration, conforming to the documented coding standard, and all source files at their correct baseline revision?
ABCD
Ref: DO-178C §11.11 source code / §5.4 coding standards
Section 4 — Verification Evidence (DAL A–D, with DAL-scaled depth)
SW-V1Software Verification Results — Are test results present showing that HLR-based tests were executed and passed, with test cases, test procedures, and test results as separate controlled documents?
ABCD
Ref: DO-178C §11.14 verification results / §6 verification objectives
SW-V2Structural Coverage Analysis — Is structural coverage evidence present at the DAL-required level: DAL A (MC/DC), DAL B (Decision/branch), DAL C (Statement)? Are uncovered code segments explained and justified?
A (MC/DC)B (Decision)C (Statement)
Ref: DO-178C §6.4 structural coverage / MC/DC requirement §6.4.4.1 (DAL A only)
SW-V3Low-Level Requirement-Based Testing — Is there evidence that LLR-based tests were executed at the target processor or equivalent, covering all LLRs? (Required DAL A and B)
AB
Ref: DO-178C §6.4.2 LLR-based testing / target platform testing objectives
SW-V4Independence of Verification — For DAL A: is verification performed by personnel independent from the development team (different person or tool with independence rationale)? Is this independence documented?
A ONLY
Ref: DO-178C §12 independence requirements / Table A-8 DAL A independence

SW-C2Problem Reports — Are all open problem reports evaluated for safety impact, with safety-relevant items resolved before certification? Is the problem report log accessible and current?
