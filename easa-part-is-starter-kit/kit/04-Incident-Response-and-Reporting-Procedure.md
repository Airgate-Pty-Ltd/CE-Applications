# Information Security Incident Response and Reporting Procedure
**[The Organization]** · Doc ID: [PLACEHOLDER] · Rev: [PLACEHOLDER]

## 1. Purpose
Define how information security events affecting the Part-IS scope are detected,
contained, investigated, recovered from, and reported.

## 2. Definitions
Event: observable occurrence. Incident: event with actual or potential adverse
effect on information security within scope. Safety-impacting incident: incident
with potential aviation-safety consequence (triggers external reporting).

## 3. Process
1. **Detect / receive** — any employee or contractor reports suspected events to
   [PLACEHOLDER: role/contact]. Detection sources: [PLACEHOLDER].
2. **Triage** — [PLACEHOLDER: role] classifies within [PLACEHOLDER] hours:
   (a) not an incident, (b) incident — no safety impact, (c) safety-impacting.
3. **Contain and recover** — actions logged on the Incident Record (below).
4. **Report externally** — safety-impacting incidents reported to
   [PLACEHOLDER: competent authority + channel] within [PLACEHOLDER: verify
   required timescale]. Interfaced organisations notified per Interface Register.
5. **Investigate** — root cause via the organisation's corrective action process.
6. **Close** — effectiveness verified; lessons fed to risk register and training.
