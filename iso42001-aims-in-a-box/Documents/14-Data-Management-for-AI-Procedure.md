## 1. Purpose

AI systems are only as trustworthy as the data behind them. This procedure sets out how
[The Organization] identifies, sources, documents, quality-checks, prepares, and retains the data
used to train, tune, test, and operate its AI systems, so that decisions about an AI system's
fitness for purpose are backed by traceable, well-understood data rather than assumption.

## 2. Scope

Applies to all data used at any stage of the AI lifecycle (Document 13) for in-scope AI systems:
training data, validation/test data, fine-tuning data, retrieval/reference data (e.g., for
retrieval-augmented systems), and operational/input data processed by a live system. Applies
whether data is collected first-party, licensed, purchased, synthetically generated, or obtained via
a third-party AI vendor.

## 3. Defined Terms

| Term | Meaning |
|---|---|
| Provenance | The documented origin of a dataset: who collected it, how, when, and under what rights/consent. |
| Data lineage | The traceable chain of transformations a dataset went through from source to the version actually used. |
| Data quality dimensions | Accuracy, completeness, consistency, timeliness, representativeness, and relevance — the criteria used to judge whether data is fit for its intended AI use. |
| Representativeness | The degree to which a dataset reflects the population/conditions the AI system will actually encounter in operation. |
| Data steward | The person accountable for the quality and appropriate use of a specific dataset. |
| Synthetic data | Data generated by an algorithm/model rather than collected from real-world observation. |

## 4. Roles & Responsibilities

| Role | Responsibility |
|---|---|
| Data Governance Lead | Owns this procedure; maintains the data inventory/lineage register. |
| Data Steward (per dataset) | Verifies provenance and quality of their assigned dataset(s); flags issues. |
| AI System Owner | Confirms data used for their system meets documented quality/provenance requirements before each lifecycle gate (Document 13). |
| Privacy/Legal Function | Confirms data collection/use has a lawful basis and reviews rights/licensing for third-party data. |
| Data Engineer/Preparer | Executes cleaning, labeling, transformation, and versioning per this procedure. |

## 5. Procedure

### 5.1 Sourcing and provenance documentation
Before a dataset is used for an in-scope AI system, the Data Steward records, at minimum: the
source, the collection method (e.g., direct collection, web-scrape, licensed acquisition, customer-
provided, synthetic generation), the applicable rights or consent basis, and the date obtained. Data
of unknown or undocumented provenance is not used for training or fine-tuning of an in-scope system
without an explicit, documented risk acceptance by [the AI System Owner / Data Governance Lead].

### 5.2 Data quality assessment
Each dataset is assessed against the six quality dimensions before use, using the Data Quality
Assessment template (Section 7.2). Where a dimension is rated below the threshold set by the AI
System Owner for that system's risk tier (Document 9), the gap and any mitigation (e.g., additional
cleaning, supplementing with more representative data, documenting as a known limitation in the
model card) is recorded.

### 5.3 Representativeness and bias considerations
The Data Steward, with the AI System Owner, assesses whether the dataset's coverage of relevant
subgroups, conditions, or edge cases reasonably matches the population the system will serve in
operation. Known gaps (e.g., underrepresentation of a demographic, geography, or use scenario) are
documented and carried into the model card (Document 15) as a known limitation, not silently
absorbed.

### 5.4 Data preparation and processing
Preparation steps (cleaning, deduplication, labeling/annotation, normalization, feature engineering,
splitting into train/validation/test) are documented in enough detail that the dataset version used
could be reconstructed or explained later. Each meaningful transformation is versioned (dataset
version identifier), and the version actually used to train/tune/test a given AI system version is
recorded against that system's record (linking to Document 13's stage-gate log).

### 5.5 Labeling/annotation quality (where applicable)
Where data is manually labeled/annotated, [The Organization] documents: who performed labeling
(internal staff, contractor, crowd-sourced platform), the labeling guidelines used, and a quality-
check method (e.g., inter-annotator agreement sampling, spot audits).

### 5.6 Data privacy and security
Personal data within a dataset is identified and handled per [The Organization]'s data protection
policy and applicable law (e.g., minimization, anonymization/pseudonymization where feasible,
access restricted to those with a need). Datasets containing personal or sensitive data are access-
logged and stored per [The Organization]'s information security controls.

### 5.7 Third-party and vendor data
Data obtained from or generated by a third-party AI provider (including data returned by an API
call to a foundation-model vendor) is subject to the same provenance and quality logging as
internally sourced data, and is additionally checked against the vendor's terms of use for
permitted downstream use (training, redistribution, retention).

### 5.8 Operational (input) data
Data submitted to a live AI system by users or upstream systems is monitored for quality drift
(e.g., a sudden shift in input distribution) as part of Document 13 Stage 5 monitoring, since
declining input quality can silently degrade output quality even without a model change.

### 5.9 Retention and disposal
Datasets are retained/disposed per the schedule in Document 12, with particular attention to:
deleting or anonymizing personal data once it is no longer needed for the documented purpose, and
retaining the specific dataset version used to train a deployed model for the life of that model
plus [the retention period in Document 12], to support later investigation if a problem emerges.

## 6. Records Generated
Data inventory/lineage register, Data Quality Assessment records (per dataset/version), labeling
guideline documents and quality-check results, data disposal log.
